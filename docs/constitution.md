# Constitución de Auto1 Risk Lens

1. **Especificación antes que código.** Todo cambio funcional debe tener una spec, alcance y criterio de aceptación.
2. **Decisiones explicables.** Cada puntuación, recomendación o cálculo debe mostrar factores, supuestos, fuente y fecha cuando existan.
3. **Incertidumbre honesta.** La ausencia de datos no equivale a buen estado; la herramienta no sustituye inspección, diagnosis ni asesoramiento profesional.
4. **Independencia comercial.** Patrocinio, afiliación o leads nunca alterarán silenciosamente el ranking técnico.
5. **Privacidad y autorización.** Minimizar datos, respetar permisos y usar solo fuentes e integraciones autorizadas.
6. **Calidad verificable.** Cada requisito debe tener pruebas o una comprobación manual documentada antes de considerarse terminado.
7. **Escala sostenible.** Priorizar MVPs medibles y arquitectura modular; no construir marketplace, financiación ni integraciones masivas antes de validar demanda y datos.
